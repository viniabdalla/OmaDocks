# Toolbar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Execute inline as authorized by the user.

**Goal:** Add the independent Toolbar and drag-out removal to both bar groups.

**Architecture:** A second bar-widget plugin in toolbar/ loads ToolbarWidget.qml from the same checkout. Dock.qml remains the only state writer, with a separate toolbarPinned array and idempotent removal IPC. Shared shortcut input handles click, drag release and cancellation; a narrow stacking binding places widget content above Omarchy's whole-widget drag MouseArea, leaving blank padding available for native movement.

**Tech Stack:** QML, Quickshell, JavaScript, Python, QtTest.

**Spec:** docs/superpowers/specs/2026-11-11-toolbar.md

## Global Constraints

- Name only Toolbar; no extra buttons or arrows.
- Preserve Trópico favorites, main dock pins and other shell configuration.
- No shell restart, installer execution, extra dock or desktop input injection.
- Follow system defaults for Terminal/browser; preserve an intentionally empty Toolbar.

## Review Focus

- Upgrade of old state must seed Toolbar once without changing other lists.
- Default applications must show selected/remove in context menus despite role-based shortcuts.
- Release outside must remove only its group, while Escape/cancel/inside release never remove.
- Native whole-widget drag overlay must not swallow shortcut gestures.
- Reconfiguration must preserve the user's later widget placement and unrelated settings.
